# Glossary — Ubiquitous Language

Every term used in specifications, architecture diagrams, and code. Agents: use these exact terms when discussing design.

## Core Domain Entities

### SearchDefinition

A saved job search query with title, location, schedule, and optional advanced filters. Stored in `searches` table. Defined in `src/shared/types.ts` (`SearchDefinition`), table schema in `src/shared/db-migrations.ts` (`searches`).

**Invariants:**

- `title` + `location` must be unique (checked via `search:check-duplicate` IPC).
- `schedule` must be one of: `manual`, `daily`, `weekly`, `monthly`.
- `filters` is a JSON object, validated at the API boundary.

### JobPosting

A single job listing scraped from Indeed or LinkedIn via ts-jobspy. Stored in `jobs` table. Defined in `src/shared/types.ts` (`JobPosting`), table schema in `src/shared/db-migrations.ts` (`jobs`).

**Invariants:**

- `status` follows the state machine defined in `src/shared/status-transitions.ts`.
- `fit` is one of: `High`, `Medium`, `Low`, `Skip`, or `null` (unscored).
- `is_new` = 1 for unseen jobs, 0 after user views job detail.
- `source` defaults to `'hiring.cafe'` (legacy, actual source is ts-jobspy).
- `(search_id, id)` is unique.

### CompanyResearch

LLM-generated research about a company for a specific job. Stored in `research` table. Defined in `src/shared/types.ts` (`CompanyResearch`), table schema in `src/shared/db-migrations.ts` (`research`).

**Structure (5 sections):**

- `overview` — Industry, size, funding, HQ
- `culture` — Company culture & values
- `news` — Recent news, product launches, layoffs, funding
- `keyPeople` — Leaders, hiring manager information
- `market` — Product & market position, competitors

**Invariants:**

- One row per job (`job_id` PK/FK).
- Generated on-demand only (never automatic). User must click "Research Company".
- Research is a prerequisite for resume/cover letter generation.

### AdaptedResume

An ATS-optimized resume tailored to a specific job, generated by the Writer→Scorer→Reviewer pipeline. Stored in `adapted_resumes` table. Defined in `src/shared/types.ts` (`AdaptedResume`), table schema in `src/shared/db-migrations.ts` (`adaptedResumes`).

**Invariants:**

- `ats_score` and `human_score` are 0–100.
- `iterations` is 1–5.
- One row per job (`job_id` PK/FK).
- Requires company research to exist before generation.

### CoverLetter

An ATS-optimized, human-authentic cover letter tailored to a specific job, generated by the same Writer→Scorer→Reviewer pipeline (Graph 2) with cover-letter-specific prompts. Stored in `cover_letters` table. Defined in `src/shared/types.ts` (`CoverLetter`), table schema in `src/shared/db-migrations.ts` (`coverLetters`).

**Invariants:**

- Same score/iteration constraints as AdaptedResume.
- Does NOT depend on AdaptedResume — can be generated independently.
- Requires company research to exist before generation.

### CareerProfile

The user's career personality profile (Colors/DISC, drivers, values, risk appetite). Stored in `career_profile` table (singleton: `id = 1`). Defined in `src/shared/state.ts` (`ColorProfile`), table schema in `src/shared/db-migrations.ts` (`careerProfile`).

**Invariants:**

- `id` is always 1 (enforced by CHECK constraint).
- `dominant_color` is one of: `Red`, `Yellow`, `Green`, `Blue`, `unknown`.
- `career_drivers`, `work_style_preferences`, `core_values` stored as JSON string arrays.
- This is the **active data source** for scoring, generation, and coaching. The `markdown` column stores a rendered export, not the source of truth.

### WorkExperience

A single work experience entry in the user's career history. Stored in `work_experiences` table. Defined in `src/shared/db-migrations.ts` (`workExperiences`).

**Invariants:**

- `id` is a UUID string.
- `end_date` can be `"present"` or an ISO date.
- `raci_roles`, `key_projects`, `quantified_achievements`, `skills_demonstrated` stored as JSON string arrays.

### ResumeDraft

The user's base "kitchen-sink" resume — a comprehensive document containing all experience, used as input by the Writer agent. Stored in `resume_draft` table (singleton: `id = 1`). Defined in `src/shared/db-migrations.ts` (`resumeDraft`).

**Invariants:**

- `id` is always 1 (enforced by CHECK constraint).
- NOT the same as AdaptedResume. This is the base input; AdaptedResume is the per-job output.

### StatusHistory

An audit log of every application status change for a job. Stored in `status_history` table. Defined in `src/shared/types.ts` (`StatusHistoryEntry`), table schema in `src/shared/db-migrations.ts` (`statusHistory`).

**Invariants:**

- `id` is auto-increment integer.
- `changed_at` defaults to `datetime('now')`.
- Transition validity is enforced in application code, not in the DB.

### GenerationState

The LangGraph state object passed between Writer, Scorer, and Reviewer nodes during document generation. Defined in `src/shared/types.ts` (`GenerationState`).

Fields: `documentType`, `baseResume`, `jobDescription`, `companyResearch`, `profileSummary`, `experiencesSummary`, `draftContent`, `iteration`, `maxIterations` (5), `atsScore`, `atsFeedback`, `humanScore`, `humanFeedback`, `passedATS` (≥85), `passedReview` (≥80).

### StreamEvent

Events emitted from main process to renderer during streaming operations. Defined in `src/shared/types.ts` (`StreamEvent`).

Types: `start`, `chunk`, `phase`, `score`, `feedback`, `personalization`, `done`, `error`.

### Conversation

Metadata for a Career Coach chat thread. Stored in `conversations` table. Defined in `src/shared/types.ts` (`Conversation`), table schema in `src/shared/db-migrations.ts` (`conversations`).

**Invariants:**

- `thread_id` matches `langgraph_checkpoints.thread_id` (join key).
- `type` is `"general"` (Career Coach chat) — distinct from per-job document generation chats.
- `title` is auto-generated from first user message (truncated to 50 chars).

## Architecture Patterns

### Module

Anything with an interface and an implementation (function, class, package, slice). Never say "component", "service", or "unit".

### Interface

Everything a caller must know to use the module: types, invariants, error modes, ordering, config. Not just the type signature.

### Implementation

The code inside the module. What callers never see.

### Depth

Leverage at the interface: a lot of behaviour behind a small interface. **Deep module** = small interface + lots of implementation. **Shallow** = interface nearly as complex as the implementation.

### Seam

Where an interface lives; a place behaviour can be altered without editing in place. Never say "boundary". Example: the `getModel()` factory is a seam — swap providers without touching callers.

### Adapter

A concrete thing satisfying an interface at a seam. Example: `ChatMistralAI` is an adapter satisfying the `BaseChatModel` interface.

### Leverage

What callers get from depth. More capability per unit of interface they learn.

### Locality

What maintainers get from depth. Change, bugs, knowledge concentrated in one place.

## Technical Infrastructure

### IPC Channel

A named Electron IPC communication path between renderer and main process. Two patterns:

- **Request/Response**: `ipcMain.handle` / `ipcRenderer.invoke` — for CRUD and DB queries.
- **Streaming**: `ipcRenderer.on` + `event.sender.send` — for AI operations >1 second.

Channels are grouped by domain: `search:*`, `job:*`, `job-search:*`, `company-research:*`, `document:*`, `conversation:*`, `storage:*`, `scheduler:*`.

### TanStack Query

Server-state management in the renderer. Handles caching, deduplication, background refetch for all IPC data. Hooks in `src/renderer/hooks/`. Mutations invalidate queries on success.

### Zustand Store

Client-only UI state in the renderer. Two stores:

- `careerStore.ts` — Career coaching chat state (messages, streaming, conversation history).
- `jobSearchStore.ts` — Job search UI state (active search ID, modal state, search logs).

Never caches server data (that's TanStack Query's job).

### LangGraph Graph

A compiled state graph defining agent workflow. Two graphs:

- **Graph 1** (Profile Coach): Router → Profile Coach / Experience Coach / Resume Coach — conversational career profile building.
- **Graph 2** (Generation): Writer → Scorer → Reviewer — per-job resume & cover letter generation with feedback loops (max 5 iterations).

Both compiled once at startup, held in module scope, invoked per-request. Defined in `src/main/generation-graph.ts` and `src/main/agent-ipc.ts`.

### SQL Checkpointer

LangGraph's persistence layer backed by `better-sqlite3`. Saves/loads conversation state for both graphs. Stored in `langgraph_checkpoints` and `langgraph_writes` tables. Replaces the previous `MemorySaver` in-memory approach.

### API Key Management

The infra layer that provisions LLM provider credentials at runtime. Replaces the dev-only `VITE_*` env var pattern with a database-backed key store. Defined in `src/shared/llm-provider.ts` (`getModel`), table schema in `src/shared/db-migrations.ts` (`providerKeys`).

**Precedence:** Env var (`VITE_*`) wins if set (dev override); otherwise the `provider_keys` database table is consulted. In production builds, no `VITE_*` vars are bundled.

### ProviderKey

A stored API key for a specific LLM provider. Stored in `provider_keys` table. Defined in `src/shared/db-migrations.ts` (`providerKeys`).

**Columns:**

- `provider` TEXT PK — one of `"anthropic"`, `"mistral"`, `"gemini"`, `"deepseek"`
- `api_key` TEXT NOT NULL
- `verified_at` TEXT (nullable ISO timestamp)

**Invariants:**

- A key is only stored after successful verification via a call to the provider's models endpoint (e.g., `GET https://api.anthropic.com/v1/models` for Anthropic).
- `verified_at` is set on initial store and on every subsequent update after verification.
- Production default provider is `"anthropic"` — the UI only exposes Anthropic key management.

### API Key Gate

A full-screen page rendered at app startup when no API key is available for the active provider (neither env var nor DB). Blocks access to the main application shell until a valid, verified key is stored. Defined in the renderer as a conditional wrapper in `App.tsx`.

### ts-jobspy

The npm library that scrapes Indeed and LinkedIn for job postings. Wrapped by `src/services/jobspy-client.ts`. Replaces the previously-documented "Hiring.cafe API" which was never implemented.

### Job Scheduler

A 60-second `setInterval` in `src/services/scheduler.ts`. Queries SQLite for due searches, queues them sequentially with 2s delay. Uses a shared `{ isRunning: boolean }` plain object as in-progress guard.
